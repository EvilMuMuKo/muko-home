# muko-home 最新经验的应用

调查基线：`EvilMuMuKo/muko-home` 主分支 V11，提交 `01fc4ffd9c8ff235c3c51cc80b9aaacbf88ec194`。结合已有 PR 的漫游、画质、手机冻结修复和 V11 厨房 / 柱体关系调整，取可验证的实现经验，重新建立本户型。

| 经验 | 新项目的落实 |
| --- | --- |
| 连续覆盖旧版设计容易出现旧物件残留 | `plan.ts` 一份新数据，房间、家具、门洞和模型共享，独立于 V6–V11 覆盖链 |
| 开着门的画面不能证明身体能走过 | 同一几何生成碰撞；活动门使用实时包络，测试封旧门、新门开闭及全屋路线 |
| 手机边走边变分辨率会产生明显模糊 | 单档稳定像素预算；手机停用全屏后处理及逐房反射捕获 |
| 全屋所有灯和镜面同时运算开销大 | 有限灯槽与阴影灯；共享环境反射，静态阴影按需更新 |
| 纹理占位后直接替换可能触发 GPU 纹理尺寸错误 | 图像完整加载后挂材质，每批渐进调度；测试全部 12 张纹理成功，不能以基础色截图冒充材质完成 |
| 触摸体验不能用键盘或传送替代 | CDP 双指触摸验证原点、独立抬指、取消、UI 排除和失焦；另外验证真实按键移动与碰墙 |
| WebGPU / WASM 不应该成为访问门槛 | 分别回退 WebGL2 / JavaScript；故障注入测试验证仍能进入 |
| 软件 Chromium 截图不是手机性能数据 | 记录测试平台，不宣称手机达到测得帧率；30Hz 仅调度上限 |
| Pages 发布需要产物和源码一致 | 保留现有 main:/ 发布方式，子项目输出到根目录 `yans-home/`，CI 核对构建差异 |

复用渲染器、设备恢复、质量分档、WASM 几何变换、UV 和已有授权 PBR 资源；重新编写户型、家具构造、照明编排、产品界面和浮动摇杆。未引入与本轮需求无关的布料、水体或游戏物理演示，以免增加手机开销。截图中的窗外景观为示意，并非现场窗景。
