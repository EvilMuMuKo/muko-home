# 图形与模拟实现

本轮基于线上版本 `36ac9b1`，保留户型、物体位置与原有动作。目标是增加材质层次和可信动态，同时控制移动端成本。原模型是程序化概念模型；接近 3A 游戏的最终观感仍需要更细的资产、经校准材质与烘焙光照，以及真机调优。

## 图形路径

| 项目 | 桌面 | 手机 |
| --- | --- | --- |
| 实际灯光槽 | 12 | 4–6 |
| 聚光灯阴影 | 2 × 1024 | 1 × 512 |
| 日光阴影 | 2048 | 1024 |
| 像素预算 | 约 300 万，DPR ≤ 1.75 | 约 150 万，DPR ≤ 1.25 |
| 后处理 | GTAO + HDR 泛光 + SMAA | 关闭 |
| 织物/木材 | sheen / clearcoat | Standard PBR |
| 动态模拟更新上限 | 60 Hz | 30 Hz |

设备内存、CPU 核心数、节流网络偏好共同决定低开销档。使用按需绘制和动态 DPR；GPU 后端与 Rapier 仅在需要时下载。手机默认首屏不会下载 WebGPU、桌面后处理或约 1.67 MB gzip 的 Rapier 模拟模块。

全设备采用按可见房间分配的灯光槽，灯具发光外观保留。灯光优先覆盖当前房间，因此与原来所有 38 盏灯同时参与着色的结果有差异。环境贴图仍通过 RoomEnvironment + PMREM 获得。

柔和地面接触阴影使用共享径向透明贴图，每房间合批，是局部遮蔽近似。静态家具按房间、材质、层与阴影状态合批；透明、嵌套活动组与沙发床、冰箱、活动椅保留独立渲染。原对象仍保留在不参与渲染的图层以供边界查询。没有引入手机端 SSR、屏幕空间全局光照或体积光。

## WASM

`src/transform.wat` 批量执行顶点矩阵变换；使用 f64 中间结果和 f32 存储，与 Three.js 的 JavaScript 结果一致。法线、切线和已有边界按 Three.js 语义更新。小几何体继续使用 JS，避免跨边界复制成本；加载失败也使用 JS。不依赖线程或跨源隔离，GitHub Pages 可直接运行。

本机 Node 基准（8,385 顶点 × 300 份，1 次热身后的 8 组样本中位数）：JS 约 200 ms，WASM 约 123 ms。只代表此批量变换工作负载，不是整站帧率或首屏加速承诺。可用 `npm run benchmark` 重测。

## 碰撞与布料

Rapier Rust/WASM 提供重力、CCD、小球弹性/摩擦和休眠。墙体按门窗洞口分段，家具使用保守世界轴对齐包围盒，活动家具对应运动学碰撞体。它是展示级碰撞近似，不是家具开合净空的施工校核；家具动作仍按原设计轨迹执行。

六片窗帘采用 Verlet 积分、结构/剪切距离约束、顶部固定点、墙面/地面与小球接触。尚未包含自碰撞、织物体积或严格双向布料/刚体耦合。开启模拟才替换原有装饰褶皱。

物理固定步长 1/60 秒，手机每次最多 30 Hz 提交画面；每帧最多追赶三步，落后时减慢模拟时间以避免阻塞。阴影最多约每六个模拟步刷新一次。后台、竖屏提示与上下文丢失时暂停并重置时间累计。

## 圣维南浅水方程

厨房水槽使用平底二维 Saint-Venant 方程，状态为 `U=(h, hu, hv)`：

```text
∂t U + ∂x F(U) + ∂z G(U) = (0, -khu, -khv)
F = (qx, qx²/h + gh²/2, qx·qz/h)
G = (qz, qx·qz/h, qz²/h + gh²/2)
qx = hu, qz = hv
```

通量实现直接使用守恒动量除以水深。采用有限体积 Rusanov 通量、CFL 自适应子步长、封闭边界零质量通量与动量阻尼。扰动注入动量，不注入水量。24 × 30 单元，浅水深度约 5.5 cm；表面高度和法线驱动水面材质。

这是浅水波动模型，不包含三维飞溅、气泡、真实折射、湿润或液体和刚体的双向耦合。

## 验证与局限

自动测试覆盖：原交互与 PNG 导出、空闲停绘、WASM 与 JS 的逐项数值一致、WASM/图形不支持时回退、WebGPU 请求及设备失效恢复、模拟按需加载与暂停、刚体不穿地面、水量守恒、静水稳定、非负水深、布料固定点及墙面/地面约束。

云端 Chromium 使用软件 SwiftShader。WebGPU 可以初始化，但完整场景触发驱动设备丢失；回退至 WebGL 的路径通过测试。尚未验证物理 GPU WebGPU 稳定性。没有 Android/iOS 真机 FPS、温控或电量数据。

`docs/baseline-validation.json` 记录与原发布版的物体边界、变换对照和实际合批统计。性能接口现在统计整帧绘制调用；旧版只显示后处理最终全屏三角形，不能直接比较这两个字段。

默认移动端首屏资源测算：原单 HTML 为 1,141,274 字节，gzip 367,097 字节；新入口与实际首屏 JS/CSS/WASM 合计 921,210 字节，gzip 合计 240,550 字节，约减少 34%。这是本地 gzip 估算，不代表网络实测时延；不包含用户点击后才下载的物理模块、桌面后处理与 WebGPU 模块。

本轮对照中 91 个对象查询项的已有边界与原版完全一致（最大有限坐标差 0 米），缺失/空边界项也一致；原对象变换未变化。静态家具的第二级房间合批把 129 个源网格合为 41 个批次，额外减少 88 次潜在绘制调用，不包括原版已有的合批收益。
