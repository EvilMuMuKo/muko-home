# V10 空间方案与需求符合性复核

**判定：概念模型符合本轮空间安排要求；现场可施工与真实使用验收仍为 BLOCKED。** 本复核以 V10 导出模型、对应设计源文件及已完成的 CPU 几何检查为准。所有坐标均为虚拟模型坐标，尚未测绘，不是施工尺寸。

## 已验证的模型结果

- **厨房与冰箱：PASS（模型范围）**。厨房虚拟边界为 `x=0–3.5m, z=3.4–5.68m`，模型记载面积由 `8.82m²` 调整为 `7.98m²`，所以该方案不是增加厨房面积。灶具中心 `(1.25, 3.815)` 和水槽中心 `(0.45, 4.70)` 保留。`0.91×0.75×1.85m` 双开门冰箱置于厨房外侧的端部空间，模型正面朝 `+x` 走廊；CPU 可见网格检查确认门扇向走廊开启。新隔墙位置及既有结构关系仍待现场确认。
- **客厅餐桌与家具转换：PASS（模型几何范围）**。日常桌位是 `1.10×0.70×0.74m`，配两把折椅；桌子及折椅在活动状态中有显式停车和移动过程，客厅没有固定咖啡桌。最终 CPU 检查对六种用餐、活动、沙发合并/分开及电视移动转换各采样 101 步；桌、椅、沙发模块和电视间未发现超过 2mm 容差的可见网格 AABB 相交。该结果只表示模型几何不相交，不证明搬运、坐姿、膝部空间或同时通行体验。
- **阅读与唱片角：PASS（虚拟几何高度）**。原吧台不承担主餐桌功能。唱片柜实际网格最高约 `0.765m`，低于 `0.900m` 窗台 `0.135m`；座椅朝向唱片柜，桌椅与灯具的模型边界分离。窗扇、把手、唱机防尘盖的实际操作净空仍需按窗型和设备复核。
- **客房迷你冰箱：PASS（模型网格）**。`0.48×0.52×0.85m` 冰箱门开启网格与展开床及衣柜模型包络不相交；床具、寝具与储物的真实联合使用仍需现场验证。
- **淋浴：PASS（模型运动范围）**。保留既有卫生洁具和排水对象，以切角底盘及内开玻璃门表达淋浴区。底盘模型可用面积约 `0.820m²`；实际门板宽度约 `0.664m`。CPU 检查采样了 101 个开合位置，门板留在模型围护范围内。该结果不等同于进出舒适度、湿区防水或排水施工验收。
- **本机渲染与全屋漫步：PASS（浏览器模型范围）。** 最终 [渲染审计](life-v10/release-render-audit.json) 于 09:44:47 UTC 记录 22 个视图（桌面及横屏手机尺寸仿真各 11）；两种配置均 `resolutionStable=true`，模型审计无问题/缺失，错误与缺失资源均为 0。最终 [全屋漫步](life-v10/whole-home-walk-audit.json) 于 09:46:02 UTC 标记 PASS：8 个房间、42 张截图，页面错误/资源失败/警告均为 0。它们验证本机 Chromium 中的最终布局渲染、导航和可见交互；横屏手机尺寸是仿真，不代表真机，也不证明现场净空。
- **反射缓存压力：PASS（本机 Chromium 功能范围）。** [辐射压力记录](life-v10/radiance-stress.json) 完成 30 次快速房间/灯光状态切换及 8 个房间顺序切换；页面、控制台、资源与已销毁纹理错误均为 0，缓存最大容量 16。此测试对象是按房间定位的局部镜面反射 PMREM，不是漫反射全局光照烘焙，也不是长时间性能验收。
- **冷启动与渐进纹理：PASS（同机对照，不代表手机或网络）。** [启动对照](life-v10/startup-load.json) 在同一 V10 模型和本机 macOS Chrome 中以隔离副本比较旧阻塞顺序与新顺序；清空 HTTP 缓存但未清 GPU shader cache。首个冷启动导航从 7133 ms 降至 4075 ms；两个热启动为 4087/3986 ms。新顺序测试中首个交互帧时 12 张细节纹理尚未载入，随后 12 张均载入、UUID 保持一致、错误为 0。该证据不外推到真实网络或手机。
- **原生全套回归：PARTIAL，单项旧注入用例失败后定向复测 PASS。** [原生验证记录](life-v10/native-validation.json) 的全套结果为 124 项预期通过、1 项意外失败、0 跳过/Flaky；失败来自已过时的编译故障注入预期。更新后的 `tests/home.spec.ts` 编译准备故障注入目标用例单独复测 PASS（7.9 秒），TypeScript 检查 PASS；不将两次运行合并表述成 125 项全套通过。最终完整 CI 以[本轮 Actions](https://github.com/EvilMuMuKo/muko-home/actions/workflows/verify.yml)对应提交的结果为准。

## 未完成的验收

- **BLOCKED：现场尺寸与结构。** 厨房隔墙平移约 `0.28m` 是概念设置；需确认墙体性质、柱位、可用净尺寸和现有门窗现场位置。承重墙及柱在模型中保留，模型不能代替结构鉴定。
- **BLOCKED：真实厨房与电器联合使用。** 冰箱仍是通用尺寸预算，型号、散热、门铰链、开门范围、抽屉及搬运路径未按产品确认。灶具供气、水槽给排水、洗碗机电源和实际管线端点未在模型中给出；两人同时操作、冰箱/洗碗机/厨房门联合开启也未作实地验证。
- **BLOCKED：真实睡眠与工作状态。** 保留主卧 `1.80×2.00m` 床垫和客房 `1.40×2.00m` 沙发床机构尺寸；双人睡眠舒适度、床品展开、衣柜及房门打开、两人同时工作与通行的联合状态尚未现场试用。
- **BLOCKED：窗与淋浴实体五金。** 唱片柜高度留有模型余量，但窗扇开启、把手、唱机防尘盖及扬尘维护未确认。淋浴的门铰、玻璃、切角、密封和现场地漏位置待同尺度核验。
- **BLOCKED：洗衣操作联合状态。** 阳台折叠台采用“洗衣机门关闭、取出篮筐、再展开”的顺序；柜门、篮筐取放、洗衣机检修及阳台通道联合净空尚待验证。
- **性能：已执行，桌面目标 FAIL / 仿真范围 PASS。** [性能记录](life-v10/performance.json)包含预热后12秒持续转向：桌面高画质约33.75fps、P95 50ms，未达60fps；横屏尺寸仿真约60.19fps、P95 16.7ms。该短时本机检查不是长期运行或真实手机验收。
- **BLOCKED / NOT RUN：现场及真实手机验收。** 现场尺寸、施工/机电、伴侣联合使用、真实家具搬运、手机触控与手机 GPU/网络启动尚未完成；浏览器视口仿真不可替代这些验证。

## 结论边界

当前版本可用于继续讨论平面与家具动作。它尚未达到实测、设备选型、结构审查、机电定位或现场试走后的 lived-use / construction acceptance；在这些证据完成前，不应把模型净空或动画结果表述成真实舒适度或施工可行性结论。

配套坐标、单位与功能端点见 [life-v10-measurements.csv](life-v10-measurements.csv)。本次证据目录含导出模型、浏览器渲染/漫步、启动、反射压力和原生验证 JSON，统一位于 [docs/life-v10/](life-v10/)。
