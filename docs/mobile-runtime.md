# 手机漫步稳定性修订

适用基线：`0e3a230`。本轮只修改运行预算、计算频率、贴图上传与光照实现，不变更户型、家具外尺寸或空间功能。

## 修复依据

用户在真实手机上反馈：进入后基本无法移动，光影随后补出，再行走仍卡顿。上一轮桌面小视口约60fps不能代表该设备可用性；旧版真实手机可用性按用户反馈记为 FAIL。

源码核对显示，交互开放后会进行全场景六面反射捕获，期间主渲染暂停；相邻房间还会引入新的光照/反射材质。漫步每帧会检查全屋矩阵、互动目标及射线，并且12张贴图可能在同一帧上传。这些成本不会因为首屏更早消失而消失。

## 手机默认预算

- 按触控指针或小视口选择手机档；固定DPR最高1.5，经济档1.25；像素上限100万/65万。转向和静止使用同一分辨率，保留原生抗锯齿、完整材质贴图和外景。
- 整个移动、碰撞与渲染步骤以30Hz为上限，并保持按需渲染；松开摇杆不继续无意义绘制。
- 手机不进行运行时整屋反射捕获或实时平面镜重绘；金属、玻璃与镜柜使用共享预过滤环境。桌面继续保留房间反射和实时镜面。
- 手机将离线数据的8个探针合并为一个房间平均L2 SH光照探针；始终保留相同光照对象，只更新9组系数。该近似没有空间遮挡/位置插值，强度上限0.35；不称作位置精确的GI。
- 手机实际灯光槽4个、经济档3个；保留太阳阴影、受限局部阴影、灯具模型与日夜交互。移动时仅在房间改变时重新分配灯光，不每走0.7m重绘阴影。
- 贴图每40ms提交一张，避免12张集中上传；材质纹理对象保持不变。下载完成与上传完成分别记录，`whenVisualReady()`等待最终完成。
- 停止对静止场景做全屋矩阵强制遍历；原地转头时不重新做静止碰撞。家具/门动画先执行，再做人物碰撞，包含最后一帧；互动候选每100ms刷新，松手和点击立即刷新。
- 手机关闭覆盖在实时画布上的控件背景模糊，保留可读底色和双摇杆尺寸。

## 可复跑方法

`npm ci && npm run build`，随后 `npm run preview -- --port 4173`。

`node scripts/mobile-performance.mjs http://localhost:4173/ result.json 4`

探针使用本机Chrome、844×390触控视口、DPR3设备输入及4倍CPU限速；实际画布DPR由运行策略限制。包括进入后立即转向20秒、等待最终视觉完成、行走+转向16秒。脚本由Grok Build初稿实现，再复核截止时间、错误状态和测量区间。

浏览器rAF间隔与实际场景绘制帧率分开记录：手机30帧上限不代表浏览器rAF也只有30帧。不能把桌面模拟的GPU能力称作手机GPU能力。

最终结果、具体构建和线上验证见本轮独立记录；新增 `tests/mobile-runtime.spec.ts` 校验手机策略、无二次反射捕获、稳定画布与受限帧数。现有防穿透、门扇推离、双摇杆、延迟贴图、日夜与闲置停止测试继续执行。闲置测试在完整视觉准备后判断，避免把渐进上传期间的有效绘制误认为空转。

真实手机新版表现仍为 NOT RUN，需以使用者设备反馈确认。桌面原有高画质目标及现场尺寸结论不因本次变更自动变为 PASS。

## 本轮受限仿真结果

同一Mac、触控844×390、设备DPR3、CPU限速4倍，未模拟手机GPU或蜂窝网络；未清空系统着色器缓存。旧版来源0e3a230，新版为当前手机运行策略。原始数据见[测量目录](mobile-performance/)。

| 版本/后端 | 可互动启动ms | 前20秒最差rAF间隔ms | 超250ms次数 | 前20秒实际绘制fps | 后16秒行走绘制fps |
|---|---:|---:|---:|---:|---:|
| 旧版 WebGPU | 5780 | 3333.2 | 7 | 26.84 | 50.14 |
| 新版 WebGPU | 5314 | 116.6 | 0 | 29.69 | 29.88 |
| 旧版 WebGL | 3262 | 3133.1 | 3 | 40.92 | 50.51 |
| 新版 WebGL | 2772 | 83.4 | 0 | 29.95 | 29.89 |

新版两条渲染路径均为30帧预算，后续行走模拟步P95约33.4ms；浏览器rAF仍可为60Hz。每个完整测量分别覆盖20秒转头与16秒行走。旧版触发2次房间捕获，新版0次。页面/资源错误均为零。新版主动减少像素与动态反射成本，不能将此称为同画质性能提升，也不能据此保证真实手机30fps。
